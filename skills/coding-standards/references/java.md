# Java 规则

目标 Java 8。以下规则应用于本次改动新增或修改的行；存量边界与定级口径见 `../SKILL.md`。

## 设计模式

**默认不引入。** 简单需求直接平铺实现。遵守 YAGNI 与 KISS：不为「像设计」抽层，也不为用模式而用模式。

### 准入矩阵

| 模式 | 严禁（直接平铺代码） | 必须（触发设计模式） |
| --- | --- | --- |
| 策略 Strategy | 仅 2 个分支，或分支体只有几行（单分支 < 10 行且不含 IO/事务） | 同一判断维度 **≥ 3 个**独立分支且分支内有实质逻辑，或已确认会持续扩展 |
| 建造者 Builder | 属性 < 5 个，或绝大多数为必填 | 属性 ≥ 5 个且多数字段可选，且需要不可变对象 |
| 单例 Singleton | 无状态工具类、仅为省内存（这类应是静态方法或 Spring 组件） | 全局唯一的有状态管理器、线程池、连接代理 |
| 工厂 Factory | `new` + setter 就能完成的 POJO/DTO | 创建过程复杂：组合多源数据、读配置、有前置流水线 |
| 模板方法 Template | 仅 1–2 行相似；为抽象而造父类导致继承层级过深 | 多个流程主骨架一致，仅一两个子步骤有差异 |

### 触发条件（可数、可查）

同一业务判断维度上满足任一条，才评估模式：

1. `if / else if` 分支数 **≥ 3**，或等价的多路 `switch` 分支 ≥ 3
2. 该维度**已确认**新分支会在同迭代或下一迭代加入（是已排期的实现，不是「可能会扩展」的预测）
3. 分支数未达阈值，但单个分支体超过 10 行实质逻辑，堆成一个长方法

不满足：直接实现，设计说明写一句「分支未达阈值，直接实现」，不需要论证为何不用模式。

满足：说明变化维度是什么、用哪个模式吸收、否掉了哪些替代方案、复用了工程里哪个既有抽象而不是新造一套。

### Java 落地偏好

**优先级：公司共享技能库 > 工程既有写法 > 本节建议。** 本节是推荐手段；与高优先级来源冲突时以高者为准，并说明冲突点。

1. **单例与 IoC**：Spring 环境下用 `@Component` / `@Service` 的默认 singleton 作用域，禁止手写饿汉式/懒汉式单例类。
2. **建造者**：工程已在用 Lombok 时用 `@Builder` 等注解；**工程未用时不要为单处引入**（引入前先确认是团队决定，不是顺手）。禁止手写 `static class Builder`，除非有链式强校验逻辑。
3. **策略去工厂化**：优先用 Spring 注入 `Map<String, X>` 或枚举自带行为，消除多余 Factory 类。注意 `Map` 注入的 key 取 bean 名，与业务枚举不天然一致——key 写错要到运行时找不到 bean 才暴露；枚举自带行为或显式注册表更可控。新引入的写法要在设计说明里点明。
4. **行为参数化优先**：评估模板方法或状态模式时，先看能否用 `Function` / `Consumer` / `Predicate` 传参替代类继承。

### 审查记录的位置

模式审查结论（是否引入、引入了什么、触发条件如何满足）写进**设计说明或 MR 描述**，不写进源码注释：与工程注释规范冲突，且属过程信息，对后来读代码的人没有长期价值。

### 始终成立

禁止靠反复修改稳定的核心抽象来加业务分支，应改为扩展。

### 定级

- 同维度分支 ≥ 3、分支内有实质逻辑，仍平铺在一个方法里 → `P2`
- 分支 ≥ 3 但只是枚举到值的单行映射 → `P3`，或按既有惯例用查表 / `Map` / 枚举自带行为，不强推模式
- 未达阈值、能直接实现却被强加抽象层（接口只有一个实现且无第二实现）→ `P3`
- 靠反复修改稳定核心类来加业务分支 → `P2`
- 绕过工程既有抽象、另造重复机制 → `P2`

## 并发

- 线程池一律用工程既有命名池（如 `ThreadPoolUtil` 及其等价物）；**生产代码禁止 `Executors.new*`**，测试代码除外。`P2`
- `CompletableFuture` 必须显式传 executor，不依赖 `ForkJoinPool.commonPool`；失败用 `exceptionally` / `handle` / `whenComplete` 处理；不留「发出去就不管」且无失败日志的异步任务。`P2`
- **事务方法内禁止起异步或并行**：事务、`ThreadLocal`、MDC、租户/安全上下文都不会传播到工作线程。`P2`
- 并发路径用线程安全类型（`ConcurrentHashMap`、`Atomic*`、按线程持有的 formatter）；跨线程共享 `HashMap`、`ArrayList`、`SimpleDateFormat`、非原子计数器 → `P2`
- 跨线程可达的共享可变状态，要么有明确同步，要么不可变，并把决定写下来。`P2`

## Java 8 语法

用仓库已经在用的写法，不要手写标准惯用法能表达的逻辑。

- 集合转换、过滤、分组、拼接、聚合用 Stream。
- 以下场景**保留 `for` 更清楚**，不要为风格硬转 Stream：顺序副作用、按业务条件提前退出、循环内处理受检异常、依赖下标、循环体写出来会变成多语句 lambda。
- Stream 管道内不做副作用：写库、发 MQ、调远程、改共享可变状态。`P2`
- `Collectors.toMap` 未给 merge 函数、而源数据可能重复键 → 抛 `IllegalStateException`。`P2`
- **`parallelStream` 禁止**用于：IO / 远程调用 / 数据库访问、事务内、集合小或规模不可控。它跑在共享的 `ForkJoinPool.commonPool`，事务上下文、`ThreadLocal`、MDC 都不会传到工作线程。需要真并行时用工程命名池 + `CompletableFuture`。`P2`
- `Optional` 只做返回值。不做字段类型、方法参数、集合元素、序列化 DTO 字段。不做未判存在的 `get()`——用 `orElse` / `orElseGet` / `orElseThrow` / `ifPresent` / `map`。`P2`
- lambda 保持短小单一职责；需要多语句或嵌套控制流的 lambda 体抽成具名方法。`P3`
- 能用方法引用代替等价 lambda 就用。`P3`
- map 的「取值判空再放回」改用 `getOrDefault` / `computeIfAbsent` / `putIfAbsent` / `merge`。`P3`

## 自查

```bash
git diff origin/test... -- '*.java' | grep -n "parallelStream\|Executors\.new\|Optional\.get()\|SimpleDateFormat\|new HashMap\|\.stream()"
```

命中后逐个判定：是否落在改动行上、是否命中上面某条规则。设计阶段没写三项决策的，先补结论再继续。
